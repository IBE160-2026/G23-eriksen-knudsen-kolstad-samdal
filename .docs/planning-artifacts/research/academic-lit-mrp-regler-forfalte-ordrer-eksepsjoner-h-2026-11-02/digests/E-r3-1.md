# Digest E-r3-1: ERP MRP behaviour for past-due starts, safety stock, and lead time versus horizon (official docs only)

Accessed 2026-11-02. Budget used: 18 tool calls (search, fetch and one local PDF read). Two retrieval problems shaped this digest:
- **SAP:** help.sap.com `/docs/...` pages render with JavaScript, and WebFetch returned only the page title for all of them (3 attempts, including the legacy `saphelp_erp60_sp` static paths). Every SAP item below is therefore **snippet-only**: it comes from search-engine result summaries, not from page text I read.
- **Oracle:** the ASCP guide page was read only up to character 100,000 of about 192,000. The tool budget ran out before the rest could be read, so some Oracle items are also snippet-only.

## Findings

1. **SAP: in-house production is scheduled backward, with forward scheduling as the fallback when the start is in the past.** Search snippet: "the system automatically switches to forward scheduling only if the start date lies in the past"; on a learning page, forward scheduling runs "if allowed".
   - Doc: *Backward Scheduling for In-House Production* (SAP ERP, MRP), SAP. No version visible.
   - URL: https://help.sap.com/docs/SAP_ERP/85d3fce10e264972a0155c8b46ecf93b/91abce5314894208e10000000a174cb4.html
   - Confidence: medium. Class: erp-behaviour. **snippet** (the page itself did not render).

2. **SAP: exception message 30 when the start date falls in the past.** Search summary: when MRP backward scheduling puts a planned order's release/start date in the past, the system switches to forward scheduling from today. Whether it does so depends on the MRP group's "Start in past" setting (OPPR). Message 30 is also raised when firming MRP types such as P1 push new proposals to the end of the planning time fence.
   - Doc: *The causes of exception message 30 in transactions MD04 and MD05*, SAP Support Content (MRP). No version visible.
   - URL: https://help.sap.com/docs/SUPPORT_CONTENT/mrp/3138697939.html
   - Confidence: low-medium (I could not see the wording). Class: erp-behaviour. **snippet**.
   - Note: the message number and the OPPR field name come only from the search summary.

3. **SAP SNC (not ERP MRP), as a cross-check: planned receipts may not carry past dates.** Snippet: a planned receipt "is not allowed to have any dates/times that lie in the past"; when backward scheduling produces a past date, "the system conducts a forward scheduling, starting on the current date/time".
   - Doc: *Scheduling of Planned Receipts*, SAP Documentation, SAP SNC 7.0.
   - URL: https://help.sap.com/doc/saphelp_snc70/7.0/en-US/b4/2b8453b794f763e10000000a4450e5/content.htm
   - Confidence: medium for SNC. Do not transfer this to ERP MRP without checking. Class: erp-behaviour. **snippet**.

4. **SAP: "Start in the past" is a Customizing parameter in days for production and process order scheduling (S/4HANA Cloud learning content).** If the order start lies further back than this number of days, the system schedules from today.
   - Docs: *Configuring Production Order Scheduling* and *Configuring Process Order Scheduling*, learning.sap.com, S/4HANA Cloud Public Edition.
   - URLs: https://learning.sap.com/courses/configuring-sap-s-4hana-cloud-public-edition-manufacturing-execution/configuring-production-order-scheduling and https://learning.sap.com/learning-journeys/configuring-sap-s-4hana-cloud-public-edition-for-manufacturing-execution/configuring-process-order-scheduling
   - Confidence: low-medium. Class: erp-behaviour. **snippet**.

5. **D365 SCM, Planning Optimization: safety stock is always fulfilled at today's date plus procurement time.**
   - Quote: "Whenever the master planning engine detects that the accumulated on-hand inventory for an item will fall below its minimum, it creates a planned order ... Therefore, the system fulfills safety stock on *Today's date* + *Procurement time*."
   - The Fulfill minimum field is ignored: "When you use Planning Optimization, the setting of this field is ignored. (Instead, the system always behaves as though **Fulfill minimum** is set to *Today's date + procurement time*.)"
   - Doc: *Safety stock fulfillment for items*, Microsoft Learn. ms.date 2026-03-26, updated 2026-09-01.
   - URL: https://learn.microsoft.com/en-us/dynamics365/supply-chain/master-planning/safety-stock-replenishment
   - Confidence: high. Class: erp-behaviour. **primary**.

6. **D365 SCM, Planning Optimization: safety stock is a constraint, not a dated demand, and real demand takes priority.**
   - Quote (comparison table): "Safety stock doesn't represent demand, and no requirement date is associated with it. Instead, it sets a constraint on the amount of inventory that must be present at all times."
   - Quote: "If fulfilling the safety stock requirement causes delays in the fulfillment of real demand ... the system deprioritizes it."
   - Docs: the page in item 5, and *Safety stock fulfillment with the deprecated master planning engine*, Microsoft Learn, ms.date 2026-05-05.
   - URL: https://learn.microsoft.com/en-us/dynamics365/supply-chain/master-planning/safety-stock-replenishment-in-deprecated-engine
   - Confidence: high. Class: erp-behaviour. **primary**.
   - Note: the two pages disagree on whether a safety stock requirement line appears on Net requirements. See Disagreements.

7. **D365 SCM, deprecated engine: the four Fulfill minimum options.**
   - **Today's date:** "met on the date when master planning runs. The system tries to fulfill the safety stock limit as soon as possible, even though the attempt might be unrealistic because of the lead time."
   - **Today's date + procurement time:** "met on the date when master planning runs, plus the purchase or production lead time. This time includes any safety margins."
   - **First issue:** "met on the date when the available inventory goes below the minimum level. Even if the available inventory is below the minimum level on the date when master planning runs, this fulfillment mode doesn't try to cover it until the next requirement comes in."
   - **Coverage time fence:** "met during the period that's specified by the **Coverage time fence** field" (to be deprecated).
   - Quote, when inventory is already below the limit: "if the available inventory is already under the safety stock limit, both the **Today's date** ... and the **Today's date + procurement time** fulfillment mode trigger the replenishment immediately."
   - Doc: *Safety stock fulfillment with the deprecated master planning engine*, Microsoft Learn, ms.date 2026-05-05 (URL as item 6).
   - Confidence: high. Class: erp-behaviour. **primary**.

8. **D365 SCM: when lead time exceeds the coverage time fence, the documentation gives setup guidance, not a run-time message.**
   - Quote: "To help avoid delays, you must ensure that the coverage time fence is longer than the total lead time. The default system value is 100 days."
   - Quote: "If delays occur, the resulting planned orders might have a date that is after today's date plus the coverage time fence."
   - Quote: "If any approved supply and demand fall outside the coverage time fence, the system doesn't load them into the engine. Therefore, they don't trigger any replenishment, and the system doesn't calculate delays."
   - The page names no warning, action or futures message for this case.
   - Doc: *Coverage time fences*, Microsoft Learn. ms.date 2026-07-27, updated 2026-10-09. Applies to Planning Optimization; the derived-requirement filtering feature applies from version 10.0.49.
   - URL: https://learn.microsoft.com/en-us/dynamics365/supply-chain/master-planning/planning-optimization/coverage-time-fence
   - Confidence: high for the quoted text. Medium for "no message exists", which rests only on the absence of any mention. Class: erp-behaviour. **primary**.

9. **Oracle EBS ASCP: past-due exceptions are defined against the plan horizon start date.**
   - Quote: "A past due sales order line is a sales order line with a schedule date earlier than the plan horizon start date."
   - Quote, past due forecast: "a forecast entry with a date earlier than the plan horizon start date. The planning engine issues this message even if the forecast is totally consumed."
   - Doc: *Oracle Advanced Supply Chain Planning Implementation and User's Guide*, chapter "Supply Chain Plan Exception Messages". Oracle EBS Release 12.1 (library E18727_01).
   - URL: https://docs.oracle.com/cd/E18727_01/doc.121/e13358/T309464T309475.htm
   - Confidence: high. Class: erp-behaviour. **primary**.

10. **Oracle ASCP: insufficient lead time and compression days.**
    - Primary text read: "Order with insufficient lead time" is issued when "A supply is firmed early and the upstream orders need to be compressed."
    - Primary text read: compression-day and overload exceptions "are generated for constrained and optimized plans only when there are firm supplies in the plans or if you select the Enforce Demand Due Dates plan option."
    - Snippet only (unread part of the page): if the engine plans an order by its lead time, "it would start in the past (before the planning horizon start date)". Compression days cover the work to recover, the days scheduled before the horizon start, and the days needed to compress if the start is moved to the horizon start.
    - Snippet only: "In unconstrained plans, dependent demand is set due on the horizon start date"; in constrained plans it is set to the start date of the supply that caused it, which can be before the horizon start.
    - Doc: as item 9.
    - Confidence: high for the read text. Medium for the snippet parts. Class: erp-behaviour. **primary + snippet**.

11. **Oracle ASCP: "Items below safety stock" exception.**
    - Snippet only: it appears when "projected available balance for a planning bucket is below the specified safety stock level for the planning bucket". The quantity is the projected available balance minus safety stock. While the quantity stays the same in successive buckets, the engine keeps the same exception and extends the To Date.
    - The name is confirmed in the primary text, in the Shortages and Excess group list. The definition is in the unread part of the page.
    - Doc: as item 9.
    - Confidence: medium. Class: erp-behaviour. **snippet** for the definition.

12. **Oracle Rapid Planning (EBS 12.1), a related product:** "order with insufficient lead time" is issued only when an order start date is scheduled before the horizon start date.
    - Doc: *Oracle Rapid Planning Implementation and User's Guide*.
    - URL: https://docs.oracle.com/cd/E18727_01/doc.121/e14573/T542242T542250.htm
    - Confidence: low-medium. Class: erp-behaviour. **snippet**.

## Disagreements

- **D365 pages on the safety stock requirement line.** *Safety stock fulfillment for items* (ms.date 2026-03-26) says "The system tracks safety stock as a requirement type ... You can see the safety stock requirement line on the **Net requirements** page if you remove the default filter". The comparison table in the deprecated-engine article (ms.date 2026-05-05) says that for Planning Optimization "The *Safety stock* requirement type isn't included and isn't shown on the **Net requirements** page." Both pages are current Microsoft Learn content and describe the same engine. Use the newer page with caution.
- **Different handling of an infeasible start.** SAP (snippet) and SAP SNC push the order start to today and schedule forward, so the finish date moves later. Oracle ASCP (snippet) keeps the due date in unconstrained plans and flags compression days instead. D365 lets planned orders fall after the coverage time fence when delays occur. These are differences in design, not contradictions between sources, but the SAP side is unverified.
